# obs-mcp

Локальный MCP-сервер для OBS через OBS WebSocket v5: статус, список сцен,
аварийное переключение на приватную сцену. Полное описание — `README.md`
(канон).

**Как переехал сюда:** `hub/docs/plans/**/*-mcp-tools-relocation.md`.

## Жёсткие правила

- **Инструмент ничего не знает про аккаунт.** Ни адреса, ни пароля, ни списка
  сцен в коде как истины: всё в env-файле проекта-владельца, путь приходит
  через `--env-file`. Соседний `.env` сервер не читает — второго пути
  конфигурации не держим.
- **Консервативный скоуп.** Нет старта/остановки стрима и записи, правок
  источников, аудио-микшера, профилей и коллекций сцен. Расширять — только
  явным решением, а не «за компанию».
- **Переключение сцен под двойным гейтом**: `OBS_SCENE_SWITCH_ENABLED=true`
  плюс confirm-токен `SWITCH_DEDUS_DEV_OBS_SCENE`. Токен — фиксированная
  строка, а не конфиг: он существует, чтобы переключение не случилось
  «по автодополнению». `obs_switch_to_private` разрешён без флага, но целевая
  сцена всё равно должна быть в `OBS_ALLOWED_SCENES`.
- **Приватная сцена — аварийный тормоз.** Если на экране всплыло личное,
  правильный ответ — `obs_switch_to_private`, а не рассуждения. Гейт-логика
  этого пути покрыта тестами: `src/server.js` экспортирует `handleToolCall`
  и поднимает stdio-транспорт только под `isMainModule()`, поэтому слой
  инструментов импортируется в тест без запуска сервера (`test/server.test.js`,
  подмена подключения к OBS через опцию `connect`).
- Пароль и содержимое env-файла не печатать никогда.
- Наверх отдаются только очищенные поля, не сырые ответы OBS.

## Проверка

```bash
npm test                                     # node --test
node --env-file=<env> src/server.js           # + tools/list по stdio
```

`Failed to connect to OBS WebSocket` при живом инстансе значит, что не запущено
само приложение OBS, — сервер тут ни при чём.
